# 10: macOS 远程桌面回流验收

**What to build:** 用户通过 Screen Sharing 或 UU Remote 操作另一台设备时，确认 n2c 与远程桌面的同值剪切板转发不会持续相互放大；失败恢复仍遵守已确认预算，并明确记录无法识别的延迟旧值边界。

**Blocked by:** 04 — 网络失败时的有界发布与重试；05 — 写入失败重试与本地新变化优先。

**Status:** ready-for-human

**Execution:** 部分验收。UU Remote 4.41.0、Screen Sharing 7.0 的 ntfy 先到/随后用户触发同值共享均未放大发布；完整故障和时序矩阵仍待人工会话验收，不能关闭此票。见[验证记录](../../../docs/clipboard-sync-validation.md)。

本票交付真实远程桌面组合的验收证据和必要的范围内修正，不新增来源过滤、历史 hash、事件去重或全局排序。需要可使用的 macOS 及远程桌面会话；缺少环境时记录阻塞，不能用模拟器替代真实软件验证后标记通过。

- [ ] 分别记录 Screen Sharing、UU Remote 的软件版本、两端系统、剪切板转发设置和测试拓扑；只使用合成文本，不读取或记录用户真实剪切板正文。
- [ ] A 复制同步文本 X，经远程桌面到达 B 时，允许 A/B 各发布一次；双方交叉收到消息不再冗余写入。第三个 peer 若已接入，应最多写入一次相同同步文本。
- [ ] 在排除网络重试的同值场景，持续多个监听周期后发布和写入计数停止增长；验收不仅检查最终剪切板内容，也检查传播次数。
- [ ] 覆盖 ntfy 先到、远程桌面先到、无私有标记和重复系统通知；验证仅尾部 CR/LF 不同仍视为相同同步文本，其他空白和中间换行遵守规格。
- [ ] 验证空文本、非文本后重新复制先前文本、自身回送先于 HTTP 响应，以及自身延迟回送不覆盖本地新内容。
- [ ] 在可控故障下验证发布重试、剪切板占用、队首过期及新本地同步状态取消旧待写任务；允许预算内的重复通知，不误判为恰好一次交付。
- [ ] 记录 X→Y 后远程桌面延迟回流 X，以及中间换行等转换的实际行为；明确 hash + origin 不能识别丢失来源的旧值，必要时建议关闭远程桌面剪切板转发。
- [ ] 仅对合成文本观察实际类型和来源声明，分别记录有无稳定元数据；不把前台应用或 Handoff 标记猜成 Screen Sharing/UU Remote 来源，不直接实现排除配置。
- [ ] 对发现的确定性回归补充项目接口级自动化测试，修正范围限于规格内行为；若需要改变已确认语义，先记录证据并重新确认，不擅自扩展协议。
- [ ] 保存可复现步骤、结果和残余限制；有代码修正时运行受影响范围的格式、构建/类型检查、lint、测试和对应真实会话复验。未执行的组合保持未验证。
