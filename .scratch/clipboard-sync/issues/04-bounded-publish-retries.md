# 04: 网络失败时的有界发布与重试

**What to build:** 本地同步文本变化遇到断线、限流或发布响应丢失时，程序在明确的内存和时间预算内按顺序尽力发送；期间继续监听和接收，最终成功或未同步都有真实结果。

**Blocked by:** 03 — macOS 正常网络下的双向同步。

**Status:** ready-for-agent

**Execution:** 已实现独立 HTTP 发布、有界 FIFO、期限/次数预算、全局 Retry-After；可控时钟和 HTTP 边界测试见[验证记录](../../../docs/clipboard-sync-validation.md)。

采用已确认的有界内存 FIFO，不改成最新值合并，不增加持久队列或 event_id 去重。本票只负责发布方向，平台后端复用共享行为。

- [ ] 默认最多 128 条、序列化正文合计 8 MiB，计入在途任务；按观察顺序发送，不 debounce。后来进入非文本状态不偷偷删除此前合法入队任务。
- [ ] 每条从观察起默认有效 60 秒，排队、退避和 HTTP 请求全部计入；同一时刻最多一个在途发布，队首成功、终止或过期后继续下一条。
- [ ] 单次 HTTP 默认最多 10 秒，每条最多 5 次尝试，包含首次；退避 1/2/4/8 秒，并以剩余有效期截断。实现规格定义的配置项，非法值显式报错。
- [ ] 队列满时丢弃最旧的未开始任务并报告，保留较新的变化；不能声称撤回已在途请求。单条超限或无可淘汰项时拒绝新任务，不绕过数量或字节上限。
- [ ] 区分权限/配置错误、可恢复连接错误、超时、429 和适用的 5xx；401/403 及不可恢复 4xx 不盲目重试，所有失败都有不泄露正文或凭据的原因。
- [ ] 429 尊重 Retry-After，冷却期作用于整个发布器，不能通过淘汰队首立即发送下一条绕过；超出任务寿命则报告过期。
- [ ] 结果未知时在预算内重试相同封装，接受服务器偶发重复通知；只有明确成功的 HTTP 响应才能确认服务器接受，不等同于其他 peer 已写入。
- [ ] WebSocket 重连和 HTTP 故障不重置 origin 或内存队列，不阻塞本地监听；进程退出后不恢复队列，不自动重放服务器历史。
- [ ] 以可控时钟和项目自有 HTTP 边界 fake 验证精确次数、期限、退避、全局冷却、FIFO、淘汰和配置；覆盖响应已丢失但服务端已接受的情况，不断言恰好一次。
- [ ] 通过复制→可控失败→恢复发布→接收端的集成测试，证明共享失败恢复接入实际路径；通过受影响范围的格式、构建/类型检查、lint、测试及最小 smoke test。
