# 06: Windows 原生双向同步（已取消）

**What to build:** Windows 用户可以将真实本地复制经 ntfy 同步给其他 peer，也能接收并写入远端同步文本；使用与 macOS 相同的文本、hash、origin 和状态协调规则。

**Blocked by:** 03 — macOS 正常网络下的双向同步。

**Status:** wontfix

**Execution:** 用户后续明确取消 Windows/WSL 支持。Windows 后端、依赖及测试已移除；以下保留原始票据作为历史，下列验收不再适用。

本票交付 Windows 平台的完整正常路径和平台生命周期。04/05 是独立的共享失败恢复增量，不是本票的开始条件；不得在后端复制它们的队列或重试逻辑。

- [ ] 在目标 Windows 版本验证剪切板格式监听、消息循环和 Unicode 读写，记录环境及依赖；不把交叉编译当作真实桌面验证。
- [ ] 双向模式启动只建立基线，真实本地同步文本变化可经 HTTP 发布并由另一 peer 接收；远端消息可进入本机剪切板。
- [ ] 观察通知和读取快照能与共享状态流程协调；核对版本/新鲜度，不将积压旧通知当成新复制，也不把 sequence number 当成应用身份。
- [ ] 在平台可用的锁和写入边界内明确完成结果；剪切板占用、读取失败、不可表示文本等显式上报，不有损转码或截断，失败不假记成功。
- [ ] 读写保持同步文本语义：尾部全部 CR/LF 去除，其余空白保留；中文、emoji、空文本和非文本转换正确。当前 hash 与原生写入读回结果一致。
- [ ] 监听窗口/线程和操作具有明确的启动、停止及回收路径；验证操作有界性，不留下关闭后仍可能执行的旧写入。
- [ ] 同值通知、远端写入通知和自身回送不产生重复发布；本地原始文本仅被观察时不被程序重写。
- [ ] 默认仅接收模式继续可用；权限、会话或后台能力不足时报告原因，不伪装为双向同步。文档说明运行所需桌面会话和依赖。
- [ ] 验证 Windows→ntfy→另一 peer 及反方向的真实路径，包含写入失败报告和监听生命周期；通过受影响目标的格式、构建/类型检查、lint、测试和 Windows smoke test。
