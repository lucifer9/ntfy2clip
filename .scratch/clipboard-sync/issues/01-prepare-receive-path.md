# 01: 整理现有接收链路，明确写入结果

**What to build:** 用户继续通过现有配置接收 ntfy 文本并写入剪切板；写入命令失败时能够看到真实失败原因，日志不再泄露正文或凭据。先整理这条现有路径，使后续协议、顺序协调和失败处理能通过项目自己的边界验证。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Execution:** 已实现接收边界、真实写入结果及日志隔离；自动化与真实路径证据见[验证记录](../../../docs/clipboard-sync-validation.md)。

范围限于已确认《剪切板监听与文本同步》规格所需的预重构和直接相关修正；本票不引入监听、上传、新协议或新的文本变换。

- [ ] 保持 n2c 入口、现有环境变量及各平台当前可用的接收写入能力；WSL 仍优先选择 Windows 剪切板，保留 Xorg 删除末尾换行的原有意图。
- [ ] 将订阅消息处理与平台写入之间的必要边界整理为可独立验证的职责，不引入泛用插件框架或无关重构。
- [ ] 启动失败、stdin 写入失败和子进程非零退出都能明确报告；只有确认成功才能返回写入成功，不再将 wait 完成等同于命令成功。
- [ ] 外部进程的 stdin、等待和回收职责明确，不留下无人监督的写入任务；为后续顺序协调提供可观察的完成结果。
- [ ] 所有受影响日志停止输出剪切板正文、TOKEN 和完整认证请求，错误上下文也不得间接携带正文或凭据。
- [ ] 通过接收入口到项目自有假写入后端的测试验证普通消息转交、topic/event 过滤及失败可见性；进程边界使用小型 fake/stub，不依赖第三方内部实现。
- [ ] 对现有可用接收路径做最小 smoke test；通过受影响目标的格式、构建/类型检查、lint 和测试。没有环境的平台明确列为未验证，不宣称行为已验证。
