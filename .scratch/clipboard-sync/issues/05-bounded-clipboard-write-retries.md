# 05: 写入失败重试与本地新变化优先

**What to build:** 收到的同步文本遇到剪切板暂时占用时有限重试；用户在等待期间产生新的本地同步状态时，旧待写内容不再覆盖它。失败或过期的消息不阻塞后续接收，超时操作不会留下晚到写入。

**Blocked by:** 03 — macOS 正常网络下的双向同步。

**Status:** ready-for-agent

**Execution:** 已实现接收 FIFO、重试、代次取消和进程终止/回收；真实桌面故障矩阵未穷尽，已验证边界见[验证记录](../../../docs/clipboard-sync-validation.md)。

只处理已收到的消息，不补服务器历史；共享状态规则由各平台复用。本票不依赖发布重试完成，也不重复实现平台观察器。

- [ ] 待写队列默认 128 条 / 8 MiB，以待写文本 UTF-8 字节计数并包含在途任务；与发送队列分开计数。满时淘汰最旧的未开始任务，单条超限或无可淘汰项则拒绝新任务，均明确报告。
- [ ] 每条从接收起默认最多 5 秒、最多 5 次尝试；单次最多 1 秒，退避 50/100/200/400 ms，不能超过剩余寿命。实现规格定义的配置项，非法值显式报错。
- [ ] 每次尝试前重新检查当前内容、有效期和本地代次；同值直接满足目标，不调用系统写入。没有新本地变化时按接收顺序处理可恢复失败。
- [ ] 已观察到的本地同步文本变化、系统清空或非文本状态，使更早接收的待写旧任务失效；取消并报告，同时正常处理可发布的本地新文本。仅末尾 CR/LF 变化不冒充同步文本变化。
- [ ] 写入失败不登记成功 hash；成功只登记预期同步文本，不把外部抢写的新内容吞掉。积压旧快照不能作为新复制重新上传。
- [ ] 队首不可恢复失败或过期后继续下一条；不能因无限重试一个内容停止接收，也不能以静默丢弃伪装成功。
- [ ] 对超时进程终止并回收；原生操作必须有界或完成协调后再核对。仅取消 Future 不算停止，不能遗留并发旧写入覆盖新剪切板。
- [ ] 仅接收、无法观察本地状态的后端明确自身能力边界，不以陈旧 hash 假装知道当前内容；已有可用写入路径不因缺监听组件失效。
- [ ] 使用假后端和可控时钟覆盖占用后成功、始终失败、队首过期、容量边界、真实新复制取消旧任务、写入通知早于完成、外部抢写和超时回收；断言实际写入次数及状态，而非仅测试内部结构。
- [ ] 完成远端消息→暂时写入失败→恢复或被本地新变化取代的集成验证；通过受影响范围的格式、构建/类型检查、lint、测试及最小 smoke test。
